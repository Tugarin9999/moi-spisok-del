# AGENTS.md

## Что это

Задача челленджа «До и после»: переделать внешний вид готового экрана «Мой Список Дел».
Три файла, без сборки, без зависимостей, без git. Вся правка — в `style.css`
(основное поле) и, при необходимости, в разметке `index.html`.

## Язык

- **Общаться с пользователем и писать комментарии в коде — на русском.**
  Это пожелание владельца репозитория, а не разовое обращение.
- Тексты интерфейса в `index.html` — тоже русские, менять язык не нужно.
- Идентификаторы в CSS и JS оставляй как есть (`taskList`, `addBtn` и т. д.):
  они не имеют русского варианта и связаны с `script.js`.

## Главное ограничение

**Логику в `script.js` не менять.** Это прямо указано в `ЗАПУСК.md` и продублировано
комментарием в первой строке файла. Задача челленджа — только вёрстка и стили.
Функциональность (добавление, отметка, удаление, счётчики) должна работаться как раньше.

## Запуск и проверка

```bash
python3 -m http.server 8000   # затем http://localhost:8000
```

Открывать `index.html` напрямую (`file://`) можно, но некоторые браузеры режут
`localStorage` на `file://` — тогда и нужен сервер. Инструментов в проекте нет
ничего: ни `package.json`, ни линтера, ни тестов, ни CI. Node в системе не
установлен. Проверка — только глазами в браузере, на ширине ~480px (жёстко
заданная ширина `#app`).

## Контракт с `script.js`

JS строит разметку задач сам и на каждом `render()` полностью пересоздаёт
содержимое списка (`list.innerHTML = ""`). Поэтому стили задач живут только
в CSS и цепляются за то, что генерирует скрипт:

| Что | Как появляется | Чем стилизовать |
|---|---|---|
| `#taskInput`, `#addBtn` | разметка в HTML | как есть |
| `#taskList` | разметка в HTML | `#taskList` |
| `#taskCount`, `#doneCount` | разметка в HTML | как есть |
| `<li>` | `createElement` | `#taskList li` |
| `<li class="done">` | **только** когда задача выполнена | `.done` |
| `<span class="task-text">` | `createElement` | `.task-text` |
| `<input type="checkbox">` | `createElement`, без класса | `#taskList input[type="checkbox"]` |
| `<button>` «удалить» | `createElement`, без класса, текст `удалить` | `#taskList li button` |

Следствия, которые легко упустить:

- **Класс `done` не ставится** для невыполненных задач — селектор должен быть
  вида `li.done`, а не «все li минус done».
- **Внутри `<li>` порядок фиксирован**: чекбокс → `span.task-text` → кнопка.
  Убрать/переставить нельзя, ломается flex-раскладка.
- **Класс или id чекбоксу из HTML не задать** — скрипт создаёт его заново при
  каждом рендере, любые атрибуты из разметки будут потеряны.
- **Любая статичная разметка внутри `<ul id="taskList">` будет уничтожена**
  первым же `render()`. Заглушка «список пуст» делается через `#taskList:empty`,
  а не через элемент в HTML.
- **У `span.task-text` уже есть ведущий пробел** — скрипт пишет
  `" " + task.text`. Не добавляй свой отступ через `::before` — будет двойной.
- Счётчики внизу обновляются из JS — их нельзя сделать «статичными» или скрыть
  без потери функции.

## Стиль, к которому идём

Подробности — в `REFERENCE.md`, здесь только то, что ломается чаще всего:

- Светлый нейтральный фон, **один** акцентный цвет, шрифт без засечек
  (`system-ui` / «Segoe UI»), никаких 3D-рамок `outset`/`inset` и
  `Times New Roman` — это всё нужно убрать, а не дополнить.
- Каждая задача — обособленная карточка, а не строка впритык.
- Выполненная задача — приглушённый цвет; сплошное зачёркивание на всю длину
  строки не делать (прямо запрещено в `REFERENCE.md`).
- Одна колонка, всё в один экран без прокрутки. Декоративный текст
  (например, `#intro`) можно сократить или убрать — это не функциональность.
- Кнопка добавления — крупная, скруглённая, заметная.

## Сдача результата

Челлендж требует **скриншоты «до» и «после»** для формы отправки. «До» —
это `ДО.png` в корне; «после» нужно снять самому, в том же состоянии
(заполненный список + отмеченная задача).

Подводный камень при съёмке: задачи хранятся в `localStorage` под ключом
`todo-list-tasks`, то есть **привязаны к origin**. `file://` и
`http://localhost:8000` — разные хранилища, поэтому на сервере список
окажется пустым. Для предсказуемой картинки задай состояние вручную
(добавь задачи, одну отметь) либо очисти `localStorage` в devtools, если
нужен вид пустого состояния.
